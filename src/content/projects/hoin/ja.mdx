### プロジェクト概要

> `hoin` は [Midori](https://github.com/faransansj) との共同制作によるプロジェクトです。

画像のキャラクター分類のためのローカルWeb UI / CLIです。

`hoin` は、Web UI / CLI / Electronアプリを提供する同名のメインリポジトリと、特定キャラクターの分類を担うモデル群で構成されています。

### 技術スタック

- **Rust**: `hoin` CLI、ファイルシステム操作、モデルパッケージの解決、画像の前処理、ONNX推論を担当。
- **ONNX Runtime**: Rustバインディング経由で利用し、アプリ固有のコードではなく移植性のある分類器アーティファクトとしてモデルを配布可能に。
- **TypeScript / Node.js**: ローカルWebサーバーとJSON API。フォルダ閲覧、サムネイル生成、モデル検出、プレビュー/適用フロー、進捗表示、取り消し操作を担当。
- **Vite+**: ブラウザUIのビルド。ローカル向けリリースパッケージに同梱できる軽さを保つ。
- **共有Rustメタデータスキーマ**: アプリと独立したモデルリポジトリの双方が使うモデルマニフェストの仕様を定義。

### 主要機能

- **CLIによる分類ワークフロー**
  - 対象ディレクトリに対して一括で分類を実行
  - ファイル移動前のドライランによるプレビューに対応
  - 移動、スキップ、失敗、分類済みのエントリやサマリーをJSONで出力
  - `--min-confidence` による信頼度のしきい値フィルタリング
- **ローカルWeb UI**
  - 許可されたローカルフォルダとモデルディレクトリを閲覧
  - サムネイル、選択中のファイル、移動先フォルダの予定、分類ステータス、進捗を表示
  - 分類プランを適用し、実行済みの移動を取り消し可能
- **モデルパッケージシステム**
  - `--model-dir`、`HOIN_MODEL_DIR`、またはローカルの `./models` 検出でモデルを選択
  - ONNXアーティファクトのパスとクラスの振り分け情報を含む `hoin-model.json` マニフェストを読み込み
  - モデルのメタデータが提供する場合、日本語ラベルを含むローカライズされた移動先パスに対応
- **リリースを見据えたパッケージング**
  - アプリケーションのリリースとモデルのリリースを分離
  - 各モデルリポジトリが学習ワークフロー、アーティファクト、リリース工程、アダプターコードを個別に管理

### 解決する課題

キャラクター画像のデータセットは、未整理のファイルが詰まったフォルダから始まることがよくあります。手作業での仕分けは時間がかかり、単調でミスも起きやすく、見た目の似たクラスが多い分類体系ではなおさらです。

`hoin` は分類を、ローカルで確認しながら進められるワークフローにすることでこの手間を減らします。

1.  モデルパッケージを選ぶ。
2.  ファイルの移動先をプレビューする。
3.  結果を確認してからプランを適用する。
4.  修正が必要なら移動を取り消す。

ワークフローはあえてローカル・シングルユーザーに限定しています。ファイルはユーザーのマシンから出ることなく、アプリはディレクトリを即座に書き換えるブラックボックスなスクリプトよりも安全に一括分類できることに注力しています。

### ハイライト

単一の分類器をハードコードしたものではなく、モデルに依存しないツールとして設計しました。CLI、Web UI、メタデータスキーマは個別にリリースされたモデルパッケージと連携できるため、コアアプリの保守性を保ちながら、各キャラクター分類器を独立して進化させられます。

最も重要な設計判断は、分類をプレビュー可能にしたことです。CLIのドライランとWeb UIのプレビュー/適用フローの両方で、ファイルシステムへの変更を実行前に明示します。ユーザーのローカル画像コレクションを再編成するツールにとって、これは欠かせない要素です。
